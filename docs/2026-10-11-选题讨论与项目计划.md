## 三、选题讨论：为什么是"生日会管家"

### 核心论点

`party-*` 五件套 + 积分商城是 35 个工具里**唯一没人碰、但链路最长、且含写操作**的能力域。评分要求里"实际使用的 Tool、调用流程"恰好是它的强项——一条链串起 **10+ 个工具、6 步深度调用**，远超一般点餐 Skill 的 3~4 步。

**真机验证已通过（2026-10-11）**：

1. `mall-points-products`（catRuleIds=1>6>20,1>6>21,1>6>22）→ 返回 **19 个在售派对商品**，全部 shopId=5（走 party-order-create 下单）：

   | 生日类 | 一起开心鸭（唐老鸭） | ¥50 (8084) | ¥138 (8516) |
   | 生日类 | 奇妙生日派对（米妮） | ¥50 (1779) | — |

### 业务价值（对应评审点）

- **对家长用户**：孩子生日会筹备是典型的高决策负荷场景（选主题→选城市→选门店→选日期→约场次→下单），MCP 把这条链完整数字化了，但没有任何现成工具帮家长一步步走完。Skill 的价值 = 把 6 步收敛为一场对话 + 生日倒数提醒 + 场次余位监控。
- **对麦当劳**：派对客单价远高于单人次麦当劳（¥45–198/人 × 成团人数），是官方重点推广但认知度低的业务。Skill 等于给派对业务做了一个对话式导购。
- **与参赛者个人契合**：用户是爸爸、运营亲子向专栏（无条件养育），场景真实、demo 故事有说服力，可附孩子生日会的真实使用叙事。

### Skill 形态（三层）

1. **派对发现层**：按城市/预算/孩子年龄/主题 IP（疯狂动物城、唐老鸭、米妮、海底小纵队……）筛商品，讲清常规版 vs 尊享版差异。
2. **场次预订层**：城市 → 门店 → 可约日期 → 场次（含余位 leftNum、成团人数 partyMin/partyMax、价格）逐级钻取，确认后 `party-order-create` 下单。**写操作前逐项确认，绝不静默下单。**
3. **筹备助手层**：下单后存本地 `data/party.json`（场次、人数、预算）；用 WorkBuddy 自动化做生日倒数提醒；生成邀请文案/亲子筹备清单；积分不足时提示攒积分路径（点餐攒积分 → 兑换）。

| 方案 | 工具链深度 | 蓝海度 | 与个人场景契合 | 风险 |

## 五、MCP 调用流程（MCP_INTEGRATION.md 的骨架，后续迭代填充实测数据）

```
mall-points-products (catRuleIds=1>6>20,1>6>21,...)   ← 拉派对商品池，用户选 spu
  └─ mall-product-detail (spuId)                       ← 看 SKU/价格/说明
      └─ query-party-city (spuId)                      ← 选城市（约 280 城）
          └─ query-party-store (code, spuId)           ← 选门店
              └─ query-party-store-date (storeCode)    ← 选日期
                  └─ query-party-store-session         ← 选场次（余位/成团人数）
                      └─ party-order-create            ← 确认后下单（写操作）
```

辅助链：`query-my-account`（积分余额）、`mall-order-list`/`mall-order-detail`（派对订单查询）、`campaign-calendar`（营销日历做提醒）。

## 八、Issue 报名注意事项（关键，照抄级别）

报名方式：在活动主项目 **`MCD-qifei/MCP-Skill-Competition`** 仓库（github.com）按标准格式发 Issue。

**Issue 格式**：

- 标题：自定义报名标题（可直接用「报名申请」）
- 正文（逐行，冒号用中文全角）：

```
【参赛申请】
项目名称：麦麦生日会管家
项目地址：https://github.com/d-ouyang/mcd-party-butler
项目简介：一句话简介
```

**官方明确提醒的坑（校验逻辑严格）**：

1. **标题和正文之间、各字段与其内容之间暂不要使用换行符**——例如「项目简介：」和简介内容写在同一行，不要「项目简介：」后换行再写内容。
2. **项目地址不要用 Markdown 格式**——写裸 URL `https://github.com/...`，不要写成 `[文字](链接)`。
3. 报名前自查：仓库为 **Public**；包含 `README.md` / `CONTEST_DECLARATION.md` / `MCP_INTEGRATION.md` / 源代码（`workbuddy.md` 如参加 WorkBuddy 专项也备好）；文件名一字不差。
4. 项目创建时间窗口合规（本仓库 git init 于 2026-10-11，在窗口内 ✅）。
5. **报名成功**：官方机器人会在 Issue 下回复成功通知；**失败**会回复原因，按原因修改后**重新提交一个 Issue** 即可（参考案例：#59 缺文件失败 → 修复后 #60 成功）。
6. 报名成功后进入 `RANKING.md` 排行榜竞争：**Star 数 > 0 且按公开 Star 排名**，前 100 展示——所以仓库要做好 README 传播位（首屏钩子 + 指数/数据亮点），报名后主动扩散求 Star。
