# 使用示例 + 生日功能移除 + 履约双方案（iter-008）

- 日期：2026-10-11 下午
- 触发：用户三点反馈——① 给出示例说清"能干什么/怎么用/价值在哪"；② 生日需手动录入门槛高，**从 skill 完全去掉**；③ 自取/麦乐送两种履约需提前明确用户诉求或双方案并行；④ 追问麦金卡/早餐卡商品是否支持配送。

## 处理结果

### 1. 生日功能：完全移除

- SKILL.md：删除「生日档案与生日提醒」小节、"四个问题"改为三个、自动化里的生日提醒删除；能力三更名「派对预订」。
- data/profile.json：删除 birthday/kids/nickname 字段，只留 commute（通勤时间 + 公司/家庭 addressId）——这是履约必需，非手动偏好。
- README：三层能力③ 重写（派对 + 积分，无生日叙事）。
- 理由成立：MCP 无生日接口，手动录入 = 门槛，与"低摩擦高频"的产品定位冲突。

### 2. 履约：双方案并行（不猜偏好）

能力一履约步重写：用户未明确指定时，**自取（含预约）与麦乐送两列账同时给**；外送需 addressId（无则引导 `delivery-create-address` 建一次永久复用）。

### 3. 卡价商品是否支持配送：无法现在验证，保留防御规则

`delivery-query-stores` 依赖 addressId，当前账户无配送地址，**外送菜单是否含卡价商品暂无法真机验证**。SKILL 保留硬规则：⚠️ 外送菜单与到店菜单是两套，卡价商品在外送的可售性与价格必须 `query-meals(orderType=2)` 实时确认，不得假设；下单前给"自取实付 vs 外送实付（含配送费/打包费）"两列账。已列入待验证清单（用户建地址后第一时间验证）。

### 4. 使用示例：README 新增「使用示例（真实对话流）」节

四个场景全部用真实实测价格：
- A 工作日早晨定时任务：决策卡 → 回复 1 → 预约自取（省 ¥10.8，零等待）
- B 办卡决策：¥9.9 体验卡单笔净省 ¥16.6 → 开卡承接
- C 随手一问：下午茶双件 ¥34→¥20.9，连"外卖费会不会吃掉折扣"都算好
- D 孩子生日会：19 主题 → 场次余位 → 10 人档总账 ¥580

每个场景后一行"价值"：不打开 App / 办卡有据 / 结论非列表 / 冷门业务一步走完。
