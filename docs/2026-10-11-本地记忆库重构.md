# 本地记忆库重构：长期订单记忆 + 偏好推荐（iter-006）

- 日期：2026-10-11 下午
- 触发：用户指出原 ledger.json 的 `monthlySaved` 语义不清，且 API 订单数据不足以做长期记忆，应本地积累用户习惯做偏好推荐

## 重构结论

数据层从"单文件账本"改为「记忆库 + 账本」双层：

| 文件 | 角色 | 生命周期 |
|---|---|---|
| `data/memory.json` | **长期记忆库**（orders 历史 + tasteProfile 口味画像 + favoriteStores） | 只增不删 |
| `data/ledger.json` | 展示层：`monthlySaved` 当月已省合计 | **由 orders 派生，可随时重算**，不独立维护 |
| `data/cards.json` | 用户手动录入的卡有效期 | 手动维护 |

### memory.json 结构（新增字段）

- orders 每单新增 `slot`（下单时档口：早餐/午餐/下午茶/夜市/宵夜）和 `storeCode`——档口习惯与门店偏好都进画像。
- tasteProfile：`clusters`（牛肉/鸡肉/早餐/咖啡等主品类权重）、`avgSpend`、`favoriteSlot`、`recalculatedAt`。
- `firstUse` 记录开始使用日期。

### SKILL.md 同步修改

1. 原「实付账本」节整体替换为「本地记忆库（长期偏好）」，含结构、写入规则、偏好推荐用法三部分。
2. 写入规则：每次真实下单追加；首次使用用 `order-list` 导入近期订单并告知用户"API 只能取到最近 N 单，之后每单自动记账"；每 3 单重算 tasteProfile；下单门店自动登记 favoriteStores。
3. 偏好推荐取材顺序：记忆库高频组合 → `frequent` 常点 → 门店人气热卖；冷启动（<3 单）明示"记忆积累中"。
4. 办卡决策器的历史维度改为：优先本地记忆库（长期积累、远超 API），不足时 `order-list` 补充。
5. README 隐私说明同步更新。

## 设计理由

- API `order-list` 实测仅返回 1 条近期订单——官方接口做不了长期记忆，这正是本地记忆库的差异化价值（与参考项目"记忆银行"思路一致但字段更精）。
- `monthlySaved` 降级为纯派生值，消除"独立维护 vs orders 不一致"的隐患。
- `slot` 字段让"档口提醒"可以个性化（比如用户常在 09:40 点早餐，提醒可提前到 09:30）。
