## 一、定案摘要

| 项 | 定案 |
|---|---|
| 中文名 | **麦麦值不值** |
| 英文名 | **McWorth** |
| 仓库 | `mcd-worth-it`（GitHub 将推 `d-ouyang/mcd-worth-it`，Public） |
| 角色人设 | 麦麦精算师——不推荐你吃什么，只算"值不值" |
| 一句话 | **别浪费你在麦麦买过的权益：这顿值不值、这张卡值不值、这张券值不值。** |
| 主线 | 高频权益场景（早餐卡 / 麦金卡 / 券 / 积分） |
| 第二模块 | 生日派对 & 积分商城兑换（月度大事，保留 6 步深链作为工具覆盖度证据） |

**与红海的差异**：别人做"推荐吃什么"（App 也能做），我们做"**你付过的钱有没有用满、这张卡要不要办**"——App 不提供，且动机来自沉没成本，天然更强。

## 二、产品定义

### 目标用户
- 买了早餐卡/麦金卡但用不满的人（沉没成本焦虑）
- 每次点单都纠结"用哪张券最划算"的人
- 想知道"办麦金卡到底值不值"的犹豫者
- 想给孩子办麦当劳生日会但不知道能办、怎么办的家长（第二模块）

### 三层能力

**① 值不值 · 每顿（高频主线，每天用）**
1. **档口感知**：`now-time-info` + 门店 `reservationTimeOptions` → 现在处于早餐/午餐/下午茶/夜市/宵夜哪一档，档口还剩多久（早餐硬截止 06:14~10:15）
2. **卡价核价**：`query-meals(reservationDate)` 取当档菜单 → 挑 `discountType` 命中的商品 → `calculate-price` 核出实付与优惠额
3. **唯一推荐**：给一个答案 + 三行理由（省了多少 / 为什么是它 / 档口提醒）
4. **实付账本**：本地 `data/ledger.json` 累计"本月已省 ¥X"

**② 值不值 · 这张卡（杀手锏，办卡决策器）**
- 扫描菜单里 `canWithOrder=true` 的商品 → 算出现价与随单购价的差额
- 结合 `order-list` 历史频次 → "过去 30 天若有麦金卡能省 ¥X，卡费 ¥Y，值/不值"
- 实测差额：全明星双人分享餐 114.5→49.9（省 64.6）、安格斯厚牛堡四件套 66→37、板烧鸡腿堡四件套 57→28、巨无霸四件套 58.5→32

**③ 值不值 · 这件大事（低频高值，月度）**
- 生日派对：商品 → 城市 → 门店 → 日期 → 场次 → 下单（6 步）
- 积分商城：`mall-points-products` + `query-my-account` 算积分兑换性价比

## 七、风险与合规红线

1. **不宣称读取卡状态**：只说"按当前账号实付价计算"。卡有效期由用户手动录入。
2. **写操作必须确认**：下单、随单购加卡、领券、派对下单——逐项列出后等明确同意。
3. **价格只信接口**：不得自行估算，一律来自 `calculate-price` / `query-meals`。
4. **Token 不入库**：`MCD_MCP_TOKEN` 环境变量，示例配置仅占位符。
5. **不下真单**：派对链接到"确认下单"为止，演示止步于成本核对，避免真实消费与取消风险。
6. **隐私**：演示截图不露手机号、会员号、订单号。

## 九、P0 验证结果（2026-10-11 下午完成）

### 1. `withOrder` 核价：验证通过，且挖出杀手级数据

`calculate-price(巨无霸四件套 9900000888, withOrder{membershipCode:"106", membershipSpecId:"880"})` 返回：

| 项 | 原价 | 实付 |
|---|---|---|
| 巨无霸四件套 | 58.5 | **32.0** |
| 麦金卡体验卡（15 天） | 9.9 | 9.9 |
| **合计** | **68.4** | **41.9**（优惠 26.5） |

**结论：随单购 ¥9.9 的麦金卡体验卡，单这一单就省 ¥26.5，净省 ¥16.6。**

这是办卡决策器最有力的 demo——不是"理论上能省"，而是核价接口给出的确定数字：**花 9.9，这一顿立刻省回 26.5**。且接口明确给出了卡名「麦金卡体验卡（15天）」与价格，可直接用于"值不值"结论。
